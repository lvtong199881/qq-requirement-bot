# 移动端设计规范

> 本文件是 [AGENTS.md](../AGENTS.md) 的子文档：做移动端界面（原型、设计稿、Flutter / React Native / 原生 / 小程序实现）时按这里来。
> 规范本身与具体项目无关。项目有品牌色时，只替换「5. 颜色」里的品牌色与中性色阶，**尺寸、字号、间距、状态要求不得随意改**。
> 依据 Apple Human Interface Guidelines 与 Material Design 3，来源见文末。

## 怎么用

| 阶段 | 用法 |
| --- | --- |
| 设计 | 先定信息层级（6.1），再套栅格（3）与字号阶梯（4），最后填组件（7） |
| 实现 | 数值只从本文档取；项目内应落成 token（颜色 / 字号 / 间距），页面里不写字面量 |
| 评审 | 直接跑第 15 节的检查清单，一条不过就不算完成 |

冲突处理：平台原生规范（HIG / Material）与本文档冲突时，**以本文档为准**；本文档没写的，按平台原生规范。

## 0. 一页速查

| 项目 | 值 |
| --- | --- |
| 设计稿基准 | 375 × 812（@1x 逻辑像素），同时验 320 宽 |
| 栅格 | 8pt 基准，4pt 半格；所有间距取 4 的倍数 |
| 页面左右边距 | 16（列表 / 内容）；20（表单 / 引导页） |
| 区块间距 | 24 / 32；同组元素 8 / 12 |
| 正文字号 | 16（默认）；系统字体下 iOS 17 / Android 16 |
| 最小字号 | 11，且只用于不承载决策的元信息 |
| 圆角 | 8（小控件）/ 12（卡片、按钮）/ 16（弹层）/ 全圆（胶囊、头像） |
| 组件尺寸 | 由「内容 + 内边距」撑开，不写死 width / height |
| 颜色 | 1 个品牌色 + 4 个语义色 + 8 档中性色 |
| 动效时长 | 微交互 100–150ms，页面转场 200–300ms |
| 主操作位置 | 屏幕下 1/3（拇指区），一屏只放 1 个 |
| 必备状态 | 加载 / 空 / 错误 三态，每个列表、每个表单都要有 |

## 1. 五条原则

**1. 内容优先。** 先排信息层级，再考虑装饰。任何视觉元素说不清「帮用户做了什么判断」就删掉。

**2. 一屏一个主任务。** 每个页面只回答一个问题：这是什么、现在什么状态、我能做什么。主操作只有一个。

**3. 拇指可达。** 高频操作放在屏幕下方 1/3；顶部只放标题、返回和低频入口。

**4. 状态可见。** 任何操作 100ms 内要有反馈；任何数据区域都要设计加载、空、错误三种样子。

**5. 克制。** 能用留白就不用分割线，能用文字就不用图标，能删就删。装饰性渐变、玻璃拟态、大面积高饱和色，除非品牌明确要求，否则不用。

## 2. 平台与设备基线

### 2.1 平台差异

| 项目 | iOS | Android |
| --- | --- | --- |
| 返回方式 | 左上角返回 + 左边缘右滑 | 系统返回手势 / 返回键 |
| 字体 | SF Pro（系统） | Roboto / 厂商字体（系统） |

跨端一致性要求：**结构、间距、字号阶梯、语义色、文案一致；控件形态跟平台**（别在 Android 上做 iOS 的返回箭头，也别反过来）。

### 2.2 尺寸与安全区

- 设计稿按逻辑像素（pt / dp）做，不按物理像素；切图另说（见 14）。
- 必验两种宽度：**320**（小屏/SE）、**375–390**（主力机型）。
- 顶部避让状态栏与刘海/挖孔（iOS 44–59pt，Android 24–48dp）；底部避让 Home Indicator / 手势条（iOS 34pt，Android 24dp）。
- 键盘弹起时，输入区与主操作必须仍可见：输入框随键盘上移，不要把「提交」压在键盘后面。
- 滚动内容可以延伸到状态栏下方（沉浸式），但**文字不能**。

## 3. 栅格与间距

- **8pt 基准、4pt 半格**：margin、padding、gap、控件尺寸都取 4 的倍数。
- 允许的间距值：`4 8 12 16 20 24 32 40 48 64`。不要出现 5、7、9、13 这类数值（需要微调时用 4 的倍数，靠视觉对齐而不是靠奇数）。
- 页面左右边距 16；卡片内边距 16；卡片之间 12。
- 区块之间 24（信息密度高时 16，最多降到 16，不能再低）。
- 列表行高由内容撑开（纵向内边距 12–16）：单行落在 56 左右、双行 72 左右、带头像 + 两行说明 88 左右；不要写死行高。

### 3.1 圆角

| 圆角 | 用在哪 |
| --- | --- |
| 8 | 输入框、小标签、缩略图 |
| 12 | 卡片、按钮、列表容器 |
| 16 | 弹层、底部面板、大图 |
| 全圆 | 胶囊标签、头像、圆形图标按钮 |

同一页面最多两种圆角（外加胶囊）。混用三种以上会显得没有体系。

### 3.2 分割线与层级

- 优先用留白分组，其次用背景明度差，最后才用分割线。
- 分割线：1px hairline，颜色用中性色 + 8%–12% 不透明度，且**从文字起始处开始**（不是通栏）。
- 层级靠留白和字重表达，不靠阴影。阴影只用于真正浮起来的层：弹窗、底部面板、悬浮按钮。

## 4. 字体

### 4.1 字号阶梯

移动端只用下面 8 档，不要临时加字号。

| Token | 字号 | 字重 | 用途 |
| --- | --- | --- | --- |
| Display | 32–34 | 600–700 | 空态、引导页、启动页大标题（一屏最多一处） |
| Title L | 24–28 | 600 | 页面主标题（大标题导航 / 详情页标题） |
| Title M | 20–22 | 600 | 区块标题、弹窗标题 |
| Title S | 17 | 600 | 卡片标题、列表主文本 |
| Body | 15–17 | 400 | 正文、消息、说明 |
| Body S | 13–14 | 400 | 次要说明、副标题、表单提示 |
| Label | 12–13 | 500–600 | 按钮、标签、Tab、分组标题 |
| Caption | 11 | 400 | 时间戳、计数、极小元信息 |

规则：

- 正文 ≥ 15，**任何正文不得低于 13**；11 只用于不承载决策的元信息（时间、版本号、计数）。
- 字重只用 400 / 500 / 600 / 700；正文不用 300（细体在手机上发虚）。
- 一行中文控制在 20–22 字（375 宽）；超过就换行或删字，不要靠缩小字号塞进去。
- 行数限制：列表标题 2 行，说明 2–3 行，超出用省略号；**关键信息不要单行截断**。
- 字体族 ≤ 2。
- 不用斜体表达强调（中文斜体难读），用字重或颜色；移动端不用下划线表示可点。

### 4.2 中英混排

- 中文用全角标点，英文/数字用半角；中英文之间、数字与单位之间留一个视觉空格（`3 分钟`、`12 条消息`）。
- 省略号用 `…`，不用三个点 `...`；不叠用感叹号、问号。
- 数字不要用中文数字混排（写 `3 条`，不写 `三条`），除非是固定文案（`一键登录`）。

### 4.3 字体缩放

- **不跟随系统字号缩放**：字号固定取阶梯值，不读取系统字体大小设置。
- 按固定字号验收即可，不必为放大场景做弹性适配；但仍不要写死高度 + `overflow: hidden`，内容换行时允许撑高。
- 不允许为了塞进一行而缩小字号，换行或删字。

## 5. 颜色

### 5.1 三层结构

**品牌色（1 个）**：主按钮、选中态、链接、进度。只用于「可操作 / 当前」的语义，不做装饰。

**语义色（4 个）**：成功、警告、错误、信息。每个语义色要准备三份：本色（图标/描边）、浅底（10%–14% 不透明度，用于胶囊和提示条）、文字加深变体。

**中性色阶（8 档）**：背景、表面、描边、四级文字。给一组可直接用的示例（按品牌微调色相即可）：

| 档位 | 浅色模式 | 深色模式 | 用途 |
| --- | --- | --- | --- |
| N0 | `#FFFFFF` | `#0F1115` | 卡片、弹层表面 |
| N1 | `#F7F8FA` | `#12151A` | 页面背景 |
| N2 | `#EFF1F4` | `#1A1E24` | 输入框底、次级表面 |
| N3 | `#E3E6EB` | `#242A32` | 分割线、描边 |
| N4 | `#C9CED6` | `#39414B` | 禁用态、占位符 |
| N5 | `#8A9099` | `#7C858F` | 辅助文字（40%–50%） |
| N6 | `#4A5058` | `#B4BCC6` | 次要文字（60%–70%） |
| N7 | `#1A1D21` | `#F2F4F7` | 主文字（87%–90%） |

### 5.2 用色规则

- 文字只用中性色阶；**语义色不直接当小字颜色**，只用它的加深变体，或「浅底 + 本色文字」的胶囊。
- 状态**不能只靠颜色**表达，至少两种载体（颜色 + 图形 + 文字）。见 5.3。
- 页面背景只用一种；卡片与背景靠 1 级明度差区分，不靠阴影。
- 禁用态：整体降低不透明度到 38%–50%，但文字仍要能读；不要用「浅灰字 + 浅灰底」糊成一片。
- 渐变、霓虹色、大面积高饱和块：除非品牌明确要求，不用。

### 5.3 状态色

| 状态 | 语义 | 本色用途 | 必须配套 |
| --- | --- | --- | --- |
| 成功 | 已完成、通过 | 图标、进度、胶囊底 | 图标 + 文字（如「已完成」） |
| 警告 / 等待 | 需要用户处理 | 图标、胶囊底、提示条 | 图标 + 文字；必要时置顶分组 |
| 错误 | 失败、阻塞、破坏性操作 | 图标、错误文案、危险按钮 | 图标 + 文字；错误文案写清原因 |
| 信息 | 中性提示 | 图标、链接 | 文字 |

同一屏不要出现三种以上语义色；状态色只标状态，不标重要性。

## 6. 布局骨架

### 6.1 页面模板

```
安全区（状态栏）
导航：标题（+ 最多 1 个操作）
内容：可滚动区域
固定底部：标签栏 / 主操作 / 输入框（在安全区内）
```

规则：

- 标题与当前 Tab / 入口名称一致，不要同一页两个名字。
- 顶部导航右侧最多 1 个操作；更多操作收进「更多」。
- 只有一个主操作，且放在拇指区（屏幕下 1/3）。危险操作与主操作间距 ≥ 16，且不同色。
- 首屏必须回答三件事：**这是什么、现在什么状态、我能做什么**。三者缺一，页面就不完整。
- 长内容用「滚动收起标题栏」，不要给标题栏加常驻阴影。

### 6.2 表单页

- 单列，标签在输入框上方（常驻，不用只靠 placeholder）。
- 输入框高度由内边距撑开（见 7.2），字段间距 16–24，错误提示在字段下方 4–8。
- 一屏放不下的表单，主按钮固定在底部；不要把「提交」放在长表单最末尾让人找。
- 必填项标 `*` 并在顶部说明；能省的字段就省。

### 6.3 列表页

- 行高：由内容 + 纵向内边距 12–16 撑开（单行约 56 / 双行约 72 / 头像 + 说明约 88），不写死。
- 结构：左（图标/头像）→ 中（主文本 + 次文本）→ 右（状态/时间/箭头）。
- **整行可点**，不要只有标题可点。
- 超过 1 屏必须有下拉刷新；分页列表底部给「加载中 / 没有更多」。
- 不要用角标数字表达「有新内容」，除非产品明确要推送语义（数字会增加解释成本）。

### 6.4 拇指区

单手可达区域约为屏幕下 1/3（375 × 812 时 y ≈ 540 以后）。高频操作放这里；左上角和右上角只放返回、菜单、关闭。

底部标签 2–5 个，超过 5 个用「更多」。

## 7. 组件规范

**总则：所有组件的宽高都自适应**——尺寸由「内容 + 内边距」撑开，不写死 `height` / `width`。需要一组控件看起来等高等宽时，统一内边距、字号和图标尺寸，而不是给固定数值。本节下面的数值都是内边距 / 间距，不是组件高度。

### 7.1 按钮

| 类型 | 内边距 | 用途 |
| --- | --- | --- |
| 主按钮（实心） | 纵向 12–14 / 横向 24 | 页面唯一主操作 |
| 次按钮（描边 / 浅底） | 纵向 12–14 / 横向 24 | 并列的次要操作 |
| 文字按钮 | 纵向 8 / 横向 12 | 弹窗内取消、行内轻操作 |
| 图标按钮 | 四周 10（图标 24） | 工具栏、输入框发送 |

- 同一排的按钮内边距一致，高度自然对齐（见本节总则）。
- 一屏最多 1 个主按钮；并列两个按钮时，左边次、右边主（破坏性操作放右边且用错误色）。
- 文案 2–6 字、动词开头：`保存` `删除` `重试` `下一步`。不要用 `确定` `提交` 这种放之四海皆准的词。
- 提交中：按钮内显示 spinner 并禁用，**不弹全屏 loading**，不重复提交。
- 禁用态降低不透明度，但文字仍可读；禁用原因要在附近说明（不是干瞪眼）。

### 7.2 输入框

- 高度由内容撑开：纵向内边距 12–14 + 16 号正文，不写死高度；圆角 8–12，浅底或无边框 + 1px 描边。
- 标签常驻；placeholder 只放示例（`例如：138 0000 0000`），不要拿它当标签。
- 键盘类型与内容匹配（数字、邮箱、电话），密码可切换明文。
- 校验时机：失焦或提交时；错误用**文字 + 图标**表示，不要只把边框变红、更不要抖动。
- 多行输入自动增高，超过 5–6 行后内部滚动，不要撑满屏幕。
- 字数限制：接近上限时才显示计数（`98/100`），平时不显示。

### 7.3 列表项

- 整行可点。
- 主文本最多 2 行，次文本 1–2 行，右侧信息不换行。
- 右侧箭头只表示「可进入下一页」；可展开、可勾选不要用箭头。
- 滑动删除必须另有可见入口（不能只有手势）。

### 7.4 卡片

- 圆角 12–16，内边距 16，卡片间距 12。
- 卡片整体可点，不要拆成「标题可点、空白不可点」。
- 最多嵌套 1 层；需要嵌套说明信息层级没理清。

### 7.5 导航

- 底部标签：2–5 个，图标 + 文字，选中态用品牌色 + 实心图标，未选中用线性图标。
- 二级页必须有标题和返回；返回遵循平台习惯（iOS 左上角 + 右滑，Android 系统返回）。
- 不要自造「点标题返回」「点空白返回」这类隐藏交互。
- 标签切换保留各页滚动位置与已加载数据，不要每次重建。

### 7.6 弹层

| 类型 | 用途 | 规则 |
| --- | --- | --- |
| 对话框 | 需要用户决策、不可忽略 | 标题写问句，正文写后果；2 个按钮；破坏性操作在右且用错误色 |
| 底部面板 | 选项列表、轻量操作 | 最多 6 项；可下滑关闭；顶部有拖拽条 |
| Toast / Snackbar | 操作结果的一次性反馈 | 1 行，2–4 秒自动消失；不承载需要决策的信息；不遮挡底部主操作 |

- 确认文案要写清后果（`删除后无法恢复`），不要只写 `确定`。
- 弹层里不要放第三个按钮，除非是中立的「稍后」。

### 7.7 加载 / 空 / 错误

| 状态 | 表现 | 规则 |
| --- | --- | --- |
| 首屏加载 | 骨架屏（列表/卡片）或居中 spinner | 超过 1 秒才显示，避免闪一下；有缓存时直接显示缓存再静默刷新 |
| 局部加载 | 行内 spinner、按钮 loading | 不遮全屏，不打断滚动 |
| 分页加载 | 底部 spinner → 「没有更多了」 | 加载失败给「点击重试」，不要静默结束 |
| 空态 | 图标/插画 + 一句说明 + 一个操作（可选） | 说明要写「为什么空」和「能做什么」 |
| 错误态 | 一句话说明 + 重试按钮 | 面向用户的错误不暴露错误码和堆栈；技术细节只在调试版显示 |

- 静默刷新（轮询、回前台）不要弹全屏 loading，不要清空已有内容。
- 失败时保留用户已输入的内容。

### 7.8 其他

- 头像：圆形，32 / 40 / 48；无头像用姓名首字 + 品牌浅色底。
- 标签/徽章：胶囊，纵向内边距 2–4 / 横向 8，由 11–12 号字撑开高度；最多 2 行，超出省略。
- 开关 / 单选 / 复选：整行可点，点标签等于点控件。
- 分割线：1px，从文字起始处开始。
- 进度条：高 4–6，圆角；分段进度用等宽小格，格间距 2–4。
- 步进/进度指示：超过 5 步不要用圆点串联，改用「第 2 步 / 共 6 步」+ 进度条。

## 8. 图标与图片

- 同一套线性图标，描边 1.5–2px，尺寸 20 / 24；选中态用同套实心版本。
- 不用 emoji 当功能图标，不混用两套图标库。
- 纯图标按钮必须有可读标签（无障碍名 / tooltip）；图标不能单独承担含义。
- 图标与文字基线对齐，图标与文字间距 4–8。
- 图片等比裁切（cover），圆角与所在卡片一致；占位用中性色块，不要用「加载失败的破图」。
- 插画只用于空态、引导页，不做页面背景装饰。

## 9. 动效

| 场景 | 时长 | 缓动 |
| --- | --- | --- |
| 按下/松开、开关、选中 | 100–150ms | ease-out |
| 展开/收起、底部面板 | 200–250ms | ease-out（进入）/ ease-in（退出） |
| 页面转场 | 200–300ms | 平台默认 |
| 拖拽跟手 | 0（跟手）+ 回弹 200–300ms | 弹簧 |

- 动效只解释因果关系：从哪来、到哪去、做了什么。纯装饰动画不要。
- 超过 400ms 的动画在手机上会被感知为卡顿。
- 系统开启「减少动态效果」后，禁用非必要动画（保留状态变化）。
- 列表滚动、刷新不加动画；骨架屏用轻微明暗呼吸，不闪烁。

---

## 10. 交互与手感

- 点击 ≤ 100ms 内要有视觉反馈（水波纹、高亮、状态变化）。
- 提交类操作必须防重复：进行中禁用按钮，成功后离开或清空，失败后允许重试。
- 破坏性操作：二次确认，或提供 5 秒撤销。
- 手势不能是唯一入口：滑动删除、长按菜单之外，必须另有可见入口。
- 不做嵌套同方向滚动；横向滚动区域要露出下一项的边缘（暗示可滑）。
- 键盘：点空白收起；输入框获得焦点时自动滚到可见位置。
- 尽量不用「下拉刷新 + 自动刷新」双机制，选一个。

---

## 11. 文案

| 场景 | 写法 | 反例 |
| --- | --- | --- |
| 按钮 | 动词，2–6 字 | 「确定」「提交」 |
| 标题 | 名词短语，与入口一致 | 「欢迎来到本页面」 |
| 空态 | 先说没有什么，再说能做什么 | 「暂无数据」 |
| 错误 | 发生了什么 + 怎么办 | 「操作失败（err 500）」 |
| 确认 | 写后果 | 「您确定要执行此操作吗？」 |
| 结果提示 | 一句话说清结果 | 「操作成功」 |

- 用用户的语言，不用系统术语（「网络不太好，重试一下」而不是「请求超时」）。
- 同一动作全 App 用同一个词：`删除` 就不要混用 `移除`。
- 不用「请稍候」「正在处理中」这类无信息量的提示，除非真的要等且没有进度。
- 不指责用户（「输入有误」而不是「你输错了」）。
- 中文全角标点，省略号 `…`，数字与单位间空格；不用感叹号堆叠。
- 长度：按钮 ≤ 6 字，标题 ≤ 12 字，Toast ≤ 20 字，空态说明 ≤ 30 字。

---

## 12. 无障碍

- 所有可交互元素有可读名称；图片有替代文本；装饰图不朗读。
- 屏幕阅读器顺序 = 视觉顺序；不要用绝对定位把朗读顺序打乱。
- 颜色不单独承载信息（见 5.3）。
- 焦点态可见（外接键盘、开关控制）；焦点环清晰可辨。
- 不自动播放音视频；有声音的反馈必须同时有视觉反馈。
- 手势操作都要有非手势的替代路径。

---

## 13. 深色模式与多端适配

**深色模式**

- 必须单独设计，不是把浅色反相：背景 `#0F1115`–`#12151A`，表面按层级提亮 2%–4%。
- 不用纯黑背景、不用纯白正文（用 87% 白），避免眩光和光晕。
- 语义色在深色下重新取值（提亮、降饱和），不要直接复用浅色值。
- 图片/插画提供深色版本，或加中性遮罩；透明 PNG 在深色下要检查边缘。
- 深色下文字与语义色重新取值后单独验一遍。

**多端**

- 平板 / 折叠屏：宽度 ≥ 600 时内容限宽 600–720 居中；可选双栏（列表 + 详情），但不要拉伸单栏。
- 横屏：至少不破版；视频、图表、编辑器类页面可专门支持。
- 小屏（320）：优先减少左右边距到 12、缩图标，不要缩字号。
- 尺寸单位用逻辑像素：iOS `pt`、Android `dp`、Flutter 逻辑像素；不写物理像素。

---

## 14. 设计交付

- **命名三段式**：`组件 / 变体 / 状态`，如 `Button/Primary/Disabled`、`Card/Thread/Waiting`。
- 每个组件至少交付 5 态：默认、按下、禁用、加载、错误。
- 标注只标 token（`Brand/Primary`、`Text/Secondary`、`Radius/12`），不标散值 hex。
- 切图：矢量优先；位图只给 @3x；图标统一 24 网格、2px 内边距。
- 交互说明写清：手势、转场、异常分支（无网、超时、权限不足）。
- 交付物里不出现「这个颜色好看」这类无法落地的描述，全部落到数值。

## 15. 评审清单

**布局**

- [ ] 左右边距 16（表单 20），间距全部是 4 的倍数
- [ ] 320 / 375 两种宽度都不溢出、不重叠
- [ ] 顶部和底部都避开了安全区，键盘弹起时主操作可见
- [ ] 圆角不超过两种（+ 胶囊）

**字体**

- [ ] 字号只用了阶梯里的 8 档，正文 ≥ 15
- [ ] 列表标题 ≤ 2 行，省略号正确
- [ ] 中英混排有空格，标点全角，省略号是 `…`

**颜色**

- [ ] 只有一个品牌色，语义色只用于状态
- [ ] 深色模式单独验过，不是反相
- [ ] 禁用态文字仍可读

**组件**

- [ ] 一屏只有 1 个主按钮，位置在拇指区
- [ ] 按钮文案是动词，2–6 字
- [ ] 输入框有常驻标签，键盘类型正确，错误提示在字段下方
- [ ] 所有组件都没有写死宽高，尺寸由「内容 + 内边距」撑开
- [ ] 列表整行可点，行高由内边距撑开、同类行一致
- [ ] 弹层按钮 ≤ 2 个，破坏性操作在右且为错误色

**状态**

- [ ] 每个数据区域都有加载 / 空 / 错误三态
- [ ] 首屏 loading 超过 1 秒才出现，不闪
- [ ] 静默刷新不清屏、不打断
- [ ] 提交中按钮禁用，失败后保留已输入内容

**交互与文案**

- [ ] 点击 100ms 内有反馈
- [ ] 破坏性操作有二次确认或撤销
- [ ] 手势都有可见替代入口
- [ ] 错误文案写清原因和下一步，不暴露错误码
- [ ] 同一动作全 App 用同一个词

**无障碍与交付**

- [ ] 可点元素有可读标签，图片有替代文本
- [ ] 朗读顺序与视觉顺序一致
- [ ] 组件 5 态齐全，标注用 token 不用散值
- [ ] 无网 / 超时 / 权限不足三种异常都有设计
